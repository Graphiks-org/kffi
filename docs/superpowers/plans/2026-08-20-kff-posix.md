# kff-posix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import the POSIX Panama FFM layer from `poc-koreos` into this repository as a JVM-only `kff-posix` module.

**Architecture:** Keep `kffi` unchanged as the multiplatform runtime and add `kff-posix` as an independent published JVM artifact. Port the POSIX implementation and its tests with the package `org.graphiks.kffi.posix`, while retaining direct `java.lang.foreign` usage for this first increment.

**Tech Stack:** Kotlin Multiplatform, Kotlin/JVM, Java 25 toolchain, Panama Foreign Function & Memory API, Gradle 9.7, Kotest/Kotlin test, Conventional Commits.

**Spec:** The approved migration method in the preceding conversation: start from `poc-koreos/master`, import only POSIX first, name the project `kff-posix`, and open a PR targeting `master` while following `CONTRIBUTING.md`.

## Global Constraints

- Base the work on the latest `origin/master` and keep the branch linear.
- Use branch `feat/kff-posix` because `CONTRIBUTING.md` permits `feat/*`, `fix/*`, and `chore/*` only.
- Keep `kff-posix` JVM-only; do not add `java.lang.foreign` to `commonMain`, Android, or Native source sets.
- Use JDK 25 for the toolchain and `jvmTarget` 24 to match the existing `kffi` JVM build.
- Preserve the upstream MIT copyright notice and record the source repository/commit in module documentation.
- Use package `org.graphiks.kffi.posix`; do not retain `org.graphiks.kadre` package names.
- Use Conventional Commit subjects with the allowed `shared` scope.
- Run `./gradlew :kff-posix:jvmTest` and the required `./gradlew :kffi:jvmTest` before publication.
