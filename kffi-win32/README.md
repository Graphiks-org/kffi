# kffi-win32

JVM-only Win32 bindings for `kffi`, generated by
[kextract](https://github.com/klang-toolkit/kextract) from the Windows SDK.

The Win32 generator requires the Git submodule at `kextract` revision
`e1d922eefb6b65887c6cc4bd98370ad2d7ba8b45` (the merge commit on
`kextract/master`).

The initial surface covers the functions needed for a native Win32 window and
input loop:

- `user32.dll`
- `kernel32.dll`
- `gdi32.dll`
- `dwmapi.dll`
- `ole32.dll`
- `ninput.dll`

The checked-in Kotlin package is
`org.graphiks.kffi.win32.generated`. The source is generated code; handwritten
Win32 wrappers and higher-level window abstractions belong in a separate layer.

## Managed layer

`org.graphiks.kffi.win32.managed` holds the handwritten revocable owners built
on the generated bindings: `Win32Structs` (WNDCLASSEXW/MSG Win64 layouts),
`Win32ManagedFunctions.wndProc` (revocable WNDPROC registration with
quiescence), `Win32ControlWindow` (never-shown control window),
`Win32ManagedWindow` (managed top-level window; the handler owns the
`WM_CLOSE` decision), `Win32DropServices`/`Win32DropTarget`/`Win32DropData`
(managed OLE drop frontier: balanced `OleInitialize` STA ownership, a per-HWND
`IDropTarget` COM object revoked with quiescence, and bounded `IDataObject`
reads over `HGLOBAL` copies or retained `IStream` references), and
`Win32RawInput` (managed raw-input registration: one process-lifetime mouse
registration per process with a foreign-registration preflight, and bounded
copies of relative `RAWMOUSE` deltas read during `WM_INPUT`). The generated
package stays untouched; all FFI remains in KFFI.

## Generate on Windows

Generation requires:

- Windows 10 or 11;
- JDK 25;
- Git Bash (from Git for Windows);
- Windows SDK `10.0.28000.0`, including its `um`, `shared` and `ucrt` include
  trees;
- the initialized `kextract` submodule.

The generator also downloads the source-only Microsoft CRT Headers package
`14.44.35220` into ignored build output and checks SHA-256
`852382a9aa73502b7849c1bcadfb603ba7175c4e8b60e6aba03c7de711d4ece5`.
This supplies `excpt.h` and the CRT dependencies of the SDK's `float.h`; no
Visual Studio installation or downloaded executable is run. An internet
connection is required for the first generation.

Native test input is packaged separately under the JVM classifier
`native-test-support`. Its controlled touch harness injects genuine Windows
contacts into an explicitly selected visible test window and pumps its owner
thread. `prepareForeground` confirms an unmeasured native DOWN/UP on that HWND,
plus foreground/focus readback, before collectors are installed. `drive` drains
the queue to bounded quiescence after injection. Set `KFFI_WIN32_TOUCH_TRACE=1`
to attach a bounded injection/message trace to recognizer assertion failures.
It is absent from the production jar.

`Win32InteractionContext` submits complete, copied window-owned frames with
native pointer filtering disabled (read back as zero). Screen-pixel units,
manipulation flags `0x1f` and tap flags `0x3` are read back before admission;
inertia is disabled. Optional HWND selection rejects foreign subframes.
Reset restores both configuration and the native output callback registration.

Windows SDK `10.0.28000.0` is required for reproducible committed output. It
must be installed at `C:/Program Files (x86)/Windows Kits/10/Include/10.0.28000.0`;
the script does not fall back to another SDK version or installation root.

From Git Bash at the repository root:

```bash
git submodule update --init --recursive
scripts/gen-kffi-win32.sh
```

The script requires the pinned and clean `kextract` submodule. It always runs
that submodule's `createKextractImage` task (which Gradle may report as
up-to-date) and uses only the image produced under
`third_party/kextract/build/kextract`; external distributions are not
accepted.

The generator combines the allowlists in `generation/*.yaml` and parses a
temporary header containing `windows.h` with `WIN32_LEAN_AND_MEAN` and
`NOMINMAX`. It writes into a staging directory first, then replaces the
checked-in generated package.
Review and commit the regenerated Kotlin files with the allowlist changes that
produced them. GitHub Actions compiles and tests the checked-in bindings but
does not run this generator.

The Windows CI job also runs `:kffi-win32:jvmTest`. This is a Windows-only
integration test: it initializes the generated bindings and calls real
`kernel32.dll` APIs (`GetCurrentThreadId`, `SetLastError`, `GetLastError` and
`GetModuleHandleW`).

The Windows CI job also runs `:kffi-win32:win32IntegrationTest` with
`KFFI_WIN32_INTEGRATION=1`. This integration test creates a real Win32 window,
paints four deterministic color quadrants through User32/GDI, captures the
client area with `BitBlt`/`GetDIBits`, verifies the pixels, and writes
`build/win32-integration/screenshot.png`. The screenshot directory is uploaded
as a CI artifact.

To run the screenshot integration locally from PowerShell:

```powershell
$env:KFFI_WIN32_INTEGRATION = "1"
./gradlew.bat :kffi-win32:win32IntegrationTest --no-daemon
```

To verify that the checked-in bindings match a fresh generation:

```bash
scripts/gen-kffi-win32.sh --check
```

Generation is intentionally not part of the Gradle build. After generation,
compile the module with:

```bash
./gradlew :kffi-win32:compileKotlinJvm --no-daemon
```

The Windows SDK and the generated bindings are not available on macOS or Linux;
the generator script therefore refuses to run on those hosts.

## Managed keyboard and pointer reads

`Win32Keyboard.read(virtualKey, lParam)` copies a key packet, the queue thread's
keyboard state and its current layout. Read it before `TranslateMessage` for
that packet. The returned Kotlin snapshot owns no foreign memory.
`Win32Keyboard.translate` accepts a copied 256-byte keyboard state and uses
`ToUnicodeEx` with flag `0x4`, preserving the kernel dead-key buffer. Dead keys
are marked explicitly; these observations do not implement a text-input/IME
session. Shortcut control characters are retried with Control/Alt neutralized;
printable AltGr output is preserved.

`Win32Pointer.trackLeave(hwnd)` arms `WM_MOUSELEAVE`, and `cancelLeave` cancels
it before the window is destroyed. Re-arm tracking on the next entry.
`screenToClient` returns signed coordinates. `wheelSettings` reads the native
vertical-line and horizontal-character increments; null means page scrolling,
and zero means a disabled axis. Its temporary native buffers stay inside KFFI.

`Win32InputIntegrationTest` exercises these calls against a real window and
the active thread layout when `KFFI_WIN32_INTEGRATION=1`. It does not change
the user's keyboard layout or inject hardware input. Non-US/AltGr and physical
dead-key entry still require tests with the corresponding layout and keyboard.

For local Windows JVM development, run `scripts/publish-win32-local.ps1`.
It tests and builds the two JVM jars and publishes them with Maven POM aliases as
`1.0.0-win32-phase4-local-SNAPSHOT` (override with `-Version`). The isolated
publication avoids configuring Android/NDK and Dokka on a Windows-only host.
It contains no multiplatform metadata or documentation artifacts and is not a
production release verification. Use a distinct `-local-SNAPSHOT` version and
explicitly opt the consumer into Maven local.
The local coordinates label a test alias: `Kffi.VERSION` retains the normal
build version (`1.0.0-SNAPSHOT` by default, override with `-BuildVersion`),
whose existing runtime-version test must pass before publication.

## Checked window properties

The native window API adds `Win32WindowOperations`, `Win32OwnedImage` and
`Win32PointerConfinement`. Operations stay on the HWND owner thread. Flashing
does not activate a window; FlashWindowEx's previous-state result is not an error
BOOL. Topmost levels and icon slots are read back. RGBA8 owned images use copied
premultiplied BGRA DIBs: icons at most 256x256, cursors at most 128x128. Release
an image only after removing it from the window; shared system cursors are never
owned. Closing an active custom cursor first restores the default system cursor.

Confinement is a process-brokered ClipCursor lease for the foreground HWND's
client rectangle intersected with the visible virtual desktop. A fully off-screen
client cannot acquire confinement. Acquisition refuses an existing foreign clip. Release
only clears the rectangle still observed as owned; an observable foreign
replacement withdraws ownership without clearing it. This is not raw pointer
lock or a SetCapture substitute. Call update on geometry changes and release on
focus loss/hide/cancel/teardown. Identical writes by unrelated components cannot
be distinguished by Windows readback; cooperation is required for that case.

Content protection means the exact `WDA_MONITOR` flag plus checked native
readback, covering supported Windows capture paths while DWM composes the
desktop. It is not a security boundary or a promise about every capture tool.
`showSystemMenu` and `beginMoveResize` enter real User32 nested loops; the host
must keep routing control-window messages. A move/resize needs a same-callback
pointer authority supplied by its caller. No keyboard or pointer input is forged.

`Win32WindowProperties` copies title, signed physical bounds, client size,
styles, DPI and visibility/minimize/maximize flags from a live window.
`setTitle`, `setStyle` and `setBounds` validate native errors; style changes
require `setBounds(..., frameChanged = true)` to refresh the frame.
`outerSize` converts client pixels using the actual style and window DPI,
and `monitorBounds` reads the nearest monitor. `applyTrackLimits` is only
valid during `WM_GETMINMAXINFO`, after native default initialization. It
constrains user resizing; it cannot constrain arbitrary foreign setters.
Call these on the HWND owner thread. No native buffer escapes the call.
The API requires Windows 10 version 1607 or newer, as does its DPI primitive.
The four-argument `outerSize(hwnd, width, height, style)` also preflights a
target style without modifying the window. Validate client and track-limit
dimensions including their frame before storing a constraint or invoking setters.

`Win32WindowPropertiesIntegrationTest` proves the native calls with
`KFFI_WIN32_INTEGRATION=1`. The local development publisher packages the tested JVM artifacts.

## Native text, pointer frames and interaction recognition

`Win32TextServices.open()` initializes COM on the HWND's platform STA thread.
Create a store with an accepted `Win32TextSnapshot`, explicit configuration,
limits and an application payload-reservation callback. Install the receiving
application target before calling `activate()`. Changes carry the supplied opaque
epoch; `apply()` is the application's accepted UTF-16 snapshot. One pending native
edit waits for application adoption, and later characters/locks stay bounded.
Post application writeback after a native callback returns: synchronous COM
callback writeback is rejected with `TS_E_SYNCHRONOUS`.

The managed bridge owns ITextStoreACP, composition/input-scope interfaces and
all COM references. Keep the owner-thread pump running for worker cleanup.
`revoke()` immediately gates application delivery; `close()` releases native
ownership when callbacks are quiescent. Closing a store must precede destruction
of its HWND. Native Release/Unadvise cleanup remains valid after application
revocation. Initialization failure reports a numeric HRESULT, including an
incompatible existing COM apartment, without unbalancing CoUninitialize.

`updateCursor()` takes **screen physical pixels** for the accepted epoch. Only
the accepted caret range has layout. Native selection, text or composition edits
invalidate that layout until application adoption and a new cursor update;
provisional ACP positions never inherit the previous rectangle. Other ranges return `TS_E_NOLAYOUT`, and
ACP-from-point does not guess character positions. `Win32Pointer.clientToScreen`
and `screenToClient` preserve full signed coordinates. Text-purpose scopes and
enter actions have explicit mappings; capitalization/autocorrect are hints and
do not promise that an installed IME honors them. Route the TSF key filter before
TranslateMessage, then route character messages once. IMM compatibility characters
must not duplicate a TSF commit. No hidden EDIT control or second IMM document is used.

`Win32PointerPackets.read()` must run while the real pointer message is valid.
It checks frame/pointer products and reserves native plus copied storage before
allocation. A batch owns its lease until close; recognizer processing borrows it
through all nested callbacks. Optional pressure/tilt/twist come from the mask of
each historical sample; invalid values remain absent. Native device/target values
are scalar provenance, not application identities. Close every batch on every exit.

`Win32InteractionContext.open()` verifies screen-pixel units, manipulation flags
`0x1f` and tap flags `0x3`. Process complete copied frames in native history order;
the owner deduplicates frame IDs, including across reset. Output uses incremental
translation/scale/rotation and native double-tap counts. Reset is an owner-thread,
nonreentrant operation: defer it until process/output returns. Close from a callback
revokes immediately and defers destruction until native processing is quiescent.
Inertia, touchpad pressure and precision-touchpad semantics are not configured.

Native tests use real HWNDs, COM edit sessions, injected touch frames and Ninput
callbacks. Injection confirms native touch delivery and foreground/focus before measurement;
a denied prerequisite fails instead of passing by skip. These tests do not certify
an installed Japanese/Chinese IME, physical pen/eraser hardware or mixed-monitor
candidate placement. Those require application-level manual reception. The
`native-test-support` classifier is test-only and is published separately from
the production jars.
