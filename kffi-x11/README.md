# kffi-x11

JVM-only low-level X11 bindings for `kffi`, built on the Java Foreign Function
& Memory API (Panama FFM).

The bindings are generated by kextract into the
`org.graphiks.kffi.x11.generated` package. Generated sources are refreshed
with `scripts/gen-kffi-x11.sh`; generation is not run as part of the Gradle
build.

The module depends on `org.graphiks:kffi-posix`, uses JDK 25 bytecode, and
requires a JDK 25 runtime. The contract tests do not require an X server.

## Generated and opaque boundary

All exposed native functions are generated by kextract. Functions that accept
or return native Xlib records which the pinned generator cannot lay out safely
remain generated `MemorySegment` pointer APIs: `XEvent`, `XImage`,
`XWindowAttributes`, `XWMHints`, `XGC`, and `XShmSegmentInfo` have no raw
record accessor generated here. This avoids handwritten Kotlin FFM layouts or
offsets for records with nested declarations or LP64 padding.

The generator-only `docker/kffi-x11-codegen/x11_compat.h` supplies two named
LP64 storage declarations that kextract can generate safely:
`KffiXEventStorage` (192-byte union-compatible XEvent buffer) and
`XShmSegmentInfoCompat` (32-byte padded storage layout). They are compatibility
storage declarations, not replacements for the native records passed to Xlib;
the XShm APIs remain pointer-based.
